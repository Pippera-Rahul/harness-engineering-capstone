# Harness Engineering Capstone

An original Python implementation exploring four harness-engineering systems.

## Systems
1. Stop-reason-driven agent loop for claims intake.
2. Context selection and compression under a token budget.
3. Validated, explicit harness configuration.
4. Multi-stage orchestration with checkpoints and recovery.

## Run
python3 -m unittest discover -s tests -v

## Evidence
The evidence directory contains outputs generated by running this project.
Only measured results are reported; no external model call is required for tests.

## System 4 — Multi-Stage Quality Monitoring Orchestration

The System 4 demonstration runs a four-stage workflow using simulated quality-monitoring data.

1. **Intake:** Records the shift batch.
2. **Validate:** Records validation results.
3. **Analyze:** Uses parameterized SQLite SQL to filter open, high-severity defects.
4. **Summarize:** Produces a follow-up recommendation.

### Checkpoints and State Management

The orchestrator records completed stages, results, checkpoint indices, and stage events. If a stage fails, the existing state and event history are returned.

Helper functions demonstrate:
- `create_hot_state`: Produces compact JSON state bounded by a UTF-8 byte limit.
- `should_resume`: Determines whether a checkpoint is fresh enough to resume.
- `fork_state`: Creates an independent deep copy of state.
- `filter_defects_sql`: Filters defect records using SQLite SQL.

### Run and Test

Run the demonstration:

    python3 system-4-orchestrator/run_demo.py

Run the available tests:

    python3 -m unittest discover -s tests -v

The combined test suite currently contains 35 tests. The demonstration uses simulated data, not a production monitoring system. The hot-state size is measured in serialized UTF-8 bytes, not model tokens. The resume helper evaluates checkpoint age but does not restore or execute a pipeline from a saved checkpoint.
